# Architecture: module contracts

Moved verbatim from CLAUDE.md ("Key modules and contracts", "Archipelago life") on 2026-10-22. CLAUDE.md keeps the frame pipeline and a short summary. Update the bullet of a module when its contract changes.

### Key modules and contracts

- **Combat feedback (Step 67):** `DungeonRun.recordStrike` adds `{target, by, dmg, fx, weapon, move, flags, kill, area, section, run, targetKind, shape}` to presentation-only `strike` effects. IDs are `strike:<run>:<serial>` from a separate counter, preserving `nextFX` and all combat hashes. `combatLogic.impactTier` resolves four tiers; `game/juiceLogic.js` owns freeze admission (longest same-frame hit, 0.12 s target cooldown), warning groups / progress, settings, distance volume and voice limits. `world/combatFeel.js` owns screen-local clocks, pose holds, recoil / deaths, charge / hurt / dodge / Bloom cues, rumble, spatial sounds, finish push and phase banner. `Player.freezePose(s)` restores rig transforms after advancing gameplay animation timers; it never sets `frozen` or suppresses input. `render/combatFlash.js` patches guardian toon and stencil-writing character materials; guardians have one lifetime material each with one shared compiled program so uniforms cannot leak between enemies. `combatWarnings.js` pools warning shapes and raised wave bands; magenta burning patches use an instanced variant of that shader. `shockwave.js` uses three shared instanced layers (12 impacts, six atlas marks); `combatNumbers.js` uses one digit atlas and one instanced draw; `combatHealth.js` replaces each guardian's old single sprite with one ghost-bar draw. `audio/combatSound.js` routes synthesized combat cues through a compressor and soft ceiling, varies pitch / cutoff and caps voices; `sfx.renderOffline(name)` reports peak / RMS, including `stress`. `music.impact()` ducks 3 dB for 0.25 s without undoing cutscene ducking. `JUICE` in config holds tuning; particle capacity is 640. Options stores per-screen preferences; `__game.juice.{preview,tier,settings,setSetting,summary}` previews feedback. Test yard arena has a three-dummy line. Tests: `test/juice.test.js`.
- **Input contract:** a source's `poll()` returns `{x, y, interact, cancel, jump?, interactTap?, cancelTap?, jumpTap?, menu?, menuTap?}` (**Step 47, 0.47.0:** `jump` = Space / standard Y (3) / GameCube Y (3) / the touch and phone Jump button (**Step 58** moved X off Jump; `charm?` / `charmTap?` = R / standard X (2), RB (5) / GameCube X (0), R (5) / the violet touch button; outside combat areas it is a second Jump); sources without it report false; Jump = the hop in the 3D game and also confirms in dialogs, the Bag's provisions and menus, never a world interaction; Cancel keeps the hop AND the 2 s hold-to-drop), with y up-positive and screen-up equal to world −Z. `menu` (gamepad Start = button 9 in both profiles, the phone pad's Bag button) becomes the edge-only `actions.menuPressed`, which toggles the Bag in `main.js` (`bagPanel.drive(moves, dt)`: stick left / right = tab, up / down = scroll).
  - `InputManager` applies the deadzone, edge detection and tap latches.
  - Each device (`local` = keyboard + host touch, `pad:<i>`, `phone:c-<clientId>`, `debug:<name>`) has its own `InputManager` inside [players/playerManager.js](public/js/players/playerManager.js).
  - `player.actions` has the shape `{move:{x,z}, interactPressed, cancelPressed, jumpPressed, interactHeld, cancelHeld, jumpHeld, activeSource, held}`.
- **Gamepad profiles:** [input/gamepadSource.js](public/js/input/gamepadSource.js) holds `PROFILES` and `detectProfile`.
  - `standard` means interact is button 0, cancel is button 1, jump is Y (3) and charm is X (2) or RB (5).
  - `gamecube` means interact is button 1, cancel is button 2, jump is Y (3) and charm is X (0) or R (5) (the Y / X / R indices are unconfirmed on the real adapter), with stick boost, a rest deadzone and hat-axis D-pad decoding.
  - Force a profile with `?pad=gamecube|standard`.
- **Players:**
  - `players.list` is the active players, lowest slot first; `players.p1` always exists (the screen's first player, or the hidden placeholder). `players.on('join'|'leave'|'change')`.
  - **Regroup (0.40.1):** a local player off screen for `REGROUP_DELAY_S` (3.5 s) pops next to the nearest on-screen teammate (`players.updateRegroup(dt, camera, {followCam, blocked})` in `main.js` after the camera; pure rules in [players/regroupLogic.js](public/js/players/regroupLogic.js), `test/regroup.test.js`). Only counts when the group can't fit at `CAMERA_MAX_ZOOM` (else the camera is just lagging); after 0.5 s the lost player leaves the camera framing (`_lost`) and gets an edge arrow (`playerVisuals.js`, `.hud-edge`). `FollowCamera.zoomForSpread({half, near, far})` sizes the near (down-screen) side separately; `players.extent` carries `half / near / far`.
  - The keyboard player can leave on purpose (`players.leaveLocal()` / `canLeaveLocal()`, the roster chip's leave button, only while someone else plays on this screen); it becomes the hidden placeholder and any key rejoins it in the lowest free slot. After that, P1 is an ordinary slot that can despawn.
  - A gamepad / phone giving input before the keyboard takes over P1 and the keyboard shares it; `players.splitLocal()` / `canSplitLocal()` (the J key, the split button on the shared chip, 0.38.1) give the keyboard its own player in the lowest free slot. The host table keeps slot 0 keyed `'p1'`, so releases go through `_slotDev(i, dev)`.
  - Each player has `.index`, `.colors {ui, hat, shirt, name}`, `.device`, `.frozen`, `.away`, `.parts.handSocket` / `.parts.headSocket`, `setHat(model|null)`, `setColors({hat,cuff,shirt,pants})`, `swing()`, `setPose()`, `faceToward()`, `hop()` and `teleport()`.
- **Party Games (Steps 80-82; the long form is README "Party Games" and [plan/80-party-games.md](plan/80-party-games.md)):** [game/party.js](public/js/game/party.js) is the screen runtime, [game/party/partyDomain.js](public/js/game/party/partyDomain.js) the host-authoritative, session-only `party` domain (state hashed minus the timers `t` / `gt` / `startAt`), `flowLogic.js` the pure phases / shuffle bag / board / stars, `registry.js` the twelve games' contract, [world/party/glade.js](public/js/world/party/glade.js) the lobby.
  - **Step 80e state:** `results.bonus` = `{ label, text, slots, value }` | null (the game's feat from `game/party/bonusLogic.js`; its winners earn `PARTY.bonusStars`); `ceremony` = `{ places: [{ slot, place, stars }] }` | null (the lobby after the last round of a `party`: the trophy cut, ended by the host after `PARTY.ceremony.length` s or by the request `skipCeremony`, then a FRESH party: round 0, no stars, `flow.first`; it is NOT a seventh phase, `PHASES` stays six); `attract` boolean (the kiosk's idle demo: `rosterFromTable` leaves the humans out so only the bots play). New requests: `skipCeremony` and `touch` (any screen; `touch` only bumps the host's `touches` counter), `attract { on }` (host only; needs two bots).
  - **Runtime:** `createParty({ ..., cinematic, params })`: the ceremony is one `cinematic.begin('party', { avatarsCinematic: false })` scene on every screen (`pollSkip` -> `domain.skipCeremony()`), the bodies are held on the podium steps by `party.afterAvatars` (`world/party/ceremony.js podiumSpots`), the crowd of nine is baked once into two merged poses per friend (`npc/models.js setLowDetail`, default off). `party.kiosk` (`?party&kiosk`), `party.config.attract` (kiosk or `?attract`), `players.queueing` (host: a device that found the island full keeps claiming by itself, `d.queued`), `lockOptions()` in `ui/optionsMenu.js`, `TitleCard.skip()`. Music: the attract mode calls `music.duck(PARTY.attract.duck)`.
- **World registries:** `interactables.js`, with `add`, `remove`, `restore` and `findNearest` (which measures from the surface, i.e. radius-aware), and `colliders.js`, with circle colliders and `resolveCircle`.
  - They are **module singletons**, so creating a system twice duplicates its registrations.
  - Interactable types: `tree`, `palm`, `rock`, `bush`, `flower`, `sign`, `item`, `herb`, `mushroom`, `digspot`, `campfire`, `hatrack` (appears after the first feast), `snowman` (Frostpine, decorative wobble).
- **Items and tools:**
  - [world/items.js](public/js/world/items.js): 7 ground pickups, one held item per player (`items.heldBy(p)`), and a swap-on-pickup rule.
  - [items/tools.js](public/js/items/tools.js): the table of what each tool can chop, break or dig, and `getToolAction`.
- **Harvest:** [world/harvest.js](public/js/world/harvest.js) handles shared hit counts, felling and breaking, stumps and shards, and regrowth (60 s for trees, 45 s for rocks).
  Regrowth is **not persisted**, so a reload restores everything.
- **Economy:**
  - [game/catalog.js](public/js/game/catalog.js): all item and dish definitions with inline-SVG icons, plus `RECIPES` (12; each has an `island`: 5 home, 3 Frostpine since 29b, 4 Emberleaf since 30). **Each campfire cooks only its own island's recipes** (0.31.1): `CAMPFIRE.island` + `CAMPFIRE_ISLANDS` in config (today `['home']`; Steps 33 / 37 add `frost` / `ember`), `listRecipes(island)`, the host's cook check rejects other islands' recipes, and `dishMakeable(dish, fireIslands)` keeps quests that need an uncookable dish out of `quests.available()` (a saved one is dropped on load). **Every entry has `islands`** (where it comes from / can be made: home items `['home']`, log + stone `['home','frost','ember']`, coconut `['home','ember']`, Frostpine finds `['frost']`, Emberleaf finds `['ember']`, dishes = the island whose fire cooks them; default `['home']`); Step 31's screen-local bar filters by it; the full Bag lists every item. Add new items here and every UI picks them up.
  - [game/inventory.js](public/js/game/inventory.js): the shared, saved bag.
  - `floatText(id, n, pos, player)` in `main.js` shows the floating "+1" text; the systems that hand out items (pickups, gathering, campfire cooking) change the bag on the authority (`inventory.add`) and call it on the screen of whoever got the item. `collect()` (both in one) remains a debug helper.

  - [world/gathering.js](public/js/world/gathering.js): berries, herbs, mushrooms and dig spots, **multi-island since 29b**: home's plants come from `props.handles`, Frostpine's from `world.frost.gather` (the pure plan `islands/frostGathering.js`: 12 lingonberry bushes, 16 mint, 16 chanterelles, 9 dig spots from `sampleFrostSpots`, ids `frost-bush-i` ...). Plant records have `show / hide` closures (`b.setBerries(on, k)`, `r.set(k)`), so the state machine, timers and the `gathering` sync domain are shared. Sync ids are list indices with home's first (bushes 0-6, herbs 0-11, mushrooms 0-N) and Frostpine's appended in plan order; dig-spot sids are a counter (home 1..6, Frostpine 7..15, later ones continue); a dug spot re-appears on the SAME island (`respawns: { at, isl }`, Frostpine: `frost.sampleSpots` with a random seed). Frostpine's plants are chunked instanced layers (`lingonBush`, `lingonBerries`, `mint`, `chanterelle` in `frostVisuals.js`); picked / hidden state is re-applied after `world.rebuild('frost')` through `frostRuntime.hooks`.
